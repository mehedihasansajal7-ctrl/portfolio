About this project

An ERP for a bulk-commodity trading business — fertilizer, coal, grain. Quantities are in MT, money in BDT, and every date boundary is evaluated in Asia/Dhaka.

Five job functions plus an admin work on one database: Finance publishes rates, Sales creates orders, Sales Ops approves and raises delivery orders, Warehouse dispatches, Management reads. The rules are enforced in the code and in the database itself, so they cannot be bypassed from the UI, from the API or from raw SQL.

What it does

  • Finance's rate is copied into the order and locked permanently — a later rate change can never rewrite an old order.
  • Strict per-customer delivery priority across products, enforced when a delivery order is created and again at dispatch, inside a row-locked transaction.
  • Over-allocation and over-dispatch are rejected by CHECK constraints as well as by the service layer.
  • Unique challan numbers, an immutable stock ledger plus a balance table updated in the same transaction.
  • Append-only audit log: a database trigger rejects UPDATE, DELETE and TRUNCATE.
  • Twelve reports with Excel / PDF / CSV export, plus printables for the order confirmation, delivery order and dispatch challan.
